## Implementation corrections and evidence limits

Activation exposed an overrestrictive App-read-token alphabet assumption. The actual provider credential was printable but did not match that legacy alphabet. The probe now treats it as an opaque, length-bounded printable header credential and rejects whitespace/control bytes; local regression cases cover the boundary. The failed-start token was revoked with HTTP 204 before replacement. Negative test profiles are fixed and require baseline authorization first, so a caller cannot turn a deliberately wrong run policy into another admission route.

The temporary runtime's source bytes were checked against the reviewed source; hashes are included with the receipts. No HTTP-status line was retained for initial acceptance during the runtime update; the expired-token rejection and renewed-token acceptance were logged by the final runtime. Client receipts and independently read provider metadata supply the correlation, not unauthenticated HTTP status logs alone. The initial branch-create readback briefly failed after the write; its outcome was preserved and later resolved through matching-ref/run reads rather than repeating the branch creation.

Validation of the final executable slice passed **89 Node tests** (53 contract/generator, 30 probe and six runner-client), all 11 generated-root/type checks and four Python tests. The documentation/checklist validation and `git diff --check` also passed after integrating main's PR #42. These local checks support the recorded live results and do not pass integrated application acceptance.
