# W01.4 — Installed loading and durable sessions

Issue #17; LS-EXT-003/005; local slices of AC22/AC31/AC35/AC36. Recorded 2026-10-23. [Implementation PR #52](https://github.com/alex-engvall/labstride/pull/52) binds the tested source and recorded evidence.

## Decisions, implementation and limits

The operator approved an independent public Codex example in addition to the provider-neutral core and public fixture. The selected initial Codex path enrolls an explicitly chosen existing session, keeps hooks disabled and rejects automated sends without full atomic guards. The implementation uses one existing coordinator/store/outbox, immutable run profiles and a separate durable fixture receiver. It adds no competing agent daemon, account login, target provisioner or background core timer.

The [runtime guide](../29-installed-sessions.md) defines the installed artifact, lock/profile, command, binding, handoff and bounded question/answer interfaces. Earlier migration checksums remain unchanged; v9 adds session storage. Legacy-v5 upgrade coverage was updated to actually remove all post-v5 fixture tables before replaying migrations. Nested observation writes use savepoints.

LS-EXT-003 is locally implemented, not verified for distribution. At the initial compatibility probe, LS-EXT-005 remained in_progress because actual existing-client continuity was an open gate. The subsequent [actual client proof](W01.4-client-continuity-2026-10-23.md) closes that scoped gate and advances LS-EXT-005 to implemented. Closing an issue or running fixture tests alone does not satisfy it.

## Executed local behavior

Linux x86_64, Node 24.22.0, built-in SQLite and the repository's pinned Ajv/TypeScript toolchain. The baseline 185 Node tests and type check passed before changes.

The installed loader suite executes altered manifest/module/schema rejection before evaluation, incompatible protocol rejection, blocked external module resolution, schema/configuration/permission/capability failures, rejected untrusted package-selection input, immutable active-run profiles and missing-original-artifact failure. Actual public fixture source is packaged and loaded through the same boundary used by the Codex example.

The session suite executes original start deduplication, provider identity enrollment, explicit revision-bound handoff, send/interrupt/resume/observe/close, lost reply reconciliation against an independent SQLite backend, a backend-transaction human-revision race, malformed output rejection and durable human holds. Two actual coordinator child processes are SIGKILLed after the local effect boundary: before backend execution and after the backend committed. Reconciliation retains the same operation; the backend counts respectively zero/one effects and no replay. An unknown cached read is re-observed when the original receipt becomes available. Separate CLI processes repeat the same start, recover, resume and observe without another session start.

The Codex tests use an owned synthetic Unix-socket WebSocket server. They exercise the handshake, masked client frames, fragmented replies with interleaved ping/pong, RPC correlation, disconnect/reconnect, local monotonic observation revisions, unqualified-version and unavailable-history rejection, same-thread resume with no settings override, turn-bound interrupt, uncertain-command preservation, bounded metadata-only questions, stale/resolved answer correlation and size/time limits. Installed composition rejects missing atomic guards before crossing the effect boundary and rejects hooks disabled by its profile. These tests do not demonstrate real app interaction.

The existing observation/projection suites continue to cover durable enrollment observations, duplicate/foreign/late reports, commit-before-ack, human holds and projection conflicts. No real GitHub write or SSH workspace creation is represented by those suites.

## Initial SSH compatibility probe

At the operator's request, HostUp installed one newly generated temporary public key on the explicitly selected test VPS while retaining all existing access entries. A bounded SSH inventory observed Node **22.23.2**, CLI **0.163.0** and a running managed backend **0.157.1**. The loader/runtime baseline requires Node 24.22.0; the selected adapter targets backend 0.163.0. CLI version alone does not qualify either boundary.

A temporary Unix-socket SSH tunnel connected the local Node 24 runtime to that **existing** backend. Its actual initialize response independently reported **0.157.1**. The packaged public Codex adapter then rejected effect-free validation with `unsupported_capability`, before any session enrollment or effect. This is live compatibility-rejection evidence, not a continuity pass. No thread was started, resumed, interrupted or substituted; no hook, login or daemon configuration was changed. Private hostnames, paths, addresses, keys and upstream private source are excluded from this record.

The owned SSH tunnel was closed. HostUp removed the exact temporary live access entry; a fresh inventory confirmed its fingerprint was absent and retained entries were unchanged. The local temporary private/public key files were deleted. The inactive public-key library record is not live SSH access.
