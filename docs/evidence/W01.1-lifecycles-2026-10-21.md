# W01.1 — Independent lifecycle persistence

Date: 2026-10-21. Requirement: LS-CORE-001. Issue: [#14](https://github.com/alex-engvall/labstride/issues/14).

## Executed evidence

The application composition root, core and SQLite adapter were exercised on Linux x86_64 with Node `24.22.0` and built-in SQLite `3.53.4`. Records describe synthetic resources; no real issue, SSH workspace, enrolled interactive client, workflow or deployment was mutated.

The [lifecycle tests](../../tests/lifecycle.test.mjs) exercise actual production store/bootstrap code with temporary on-disk databases:

- A separate bootstrap process reads exactly the saved independent phases, pause/checkpoint, generation, original operation, pending projection and session/turn/human revision identities.
- A test-owned coordinator child is killed with SIGKILL before commit. A trusted injected audit identity provider pauses after database writes but before the final audit/commit; restart has no partial records, revisions or audit.
- Another test-owned coordinator child commits the entire graph and is killed before acknowledging. Restart retains nine original records, one original pending operation intent and all audit snapshots.
- Two simultaneous child processes compete using the same expected revision: one commits and one receives revision_conflict, with exactly one new audit entry.
- Invalid transitions, changed ownership, duplicate generations, orphan references, unsupported versions, malformed formats and oversized payloads leave no partial writes.
- Claimed/running operations can retain outcome_unknown across restart. Ordinary transitions and evidence-free recovery are rejected; explicit reconciliation preserves the same operation. Terminal results cannot be overwritten.
- SQLite itself prevents parent deletion through foreign keys and rejects audit updates/deletes. Failed migration DDL rolls back; changed/unknown schema versions fail without a reset.

Validation: `npm run check:types`, `npm test`, Python unit tests and `python scripts/validate_docs.py` using the pinned documentation environment. The Node suite has 98 tests (89 existing plus nine lifecycle tests). Loopback and child-process tests require an executor that permits those capabilities. Python format checkers must be installed from requirements-docs.txt; missing checkers are a failed environment preflight, not a skipped check.
