# W01.4 — Operator-authorized backend upgrade

Issue #17 / LS-EXT-005. This is an operational preparation record, not a client-continuity pass. It supplements the [installed-session evidence](W01.4-installed-sessions-2026-10-23.md).

The operator explicitly authorized upgrading the selected SSH target's existing Codex backend to **0.163.0**, using a temporary HostUp SSH key and revoking that key afterward. The live key inventory retained the three pre-existing access entries. Private connection details and session identifiers are excluded from this public record.

## Executed upgrade

Before replacement, a metadata-only inventory returned 14 existing sessions, all unloaded. The CLI was 0.163.0, but the existing backend was 0.157.1 and was not controlled by the daemon-management commands. Those commands rejected management of the old process; no successful upgrade was inferred from their failure.

The old running executable was preserved in an operator-owned restricted backup directory. Its process identity was checked against the executable's SHA-256 before a graceful SIGTERM. The process exited. Only then was durable daemon management bootstrapped from the installed CLI. `daemon update --from-cli --yes` subsequently selected and pinned **0.163.0**, disabling implicit production-version selection. The daemon's version report returned both managed and running versions as 0.163.0.

A separate connection through the existing Unix-socket endpoint received an actual initialize response reporting **0.163.0**. A second metadata-only inventory returned the same 14 session IDs, with no missing identity. This proves persisted-session retention across the upgrade; it does not prove that the interactive app resumed an enrolled session.

The target's public SSH access was independently restricted during another operator task. This upgrade continued over the existing VPN with the previously verified SSH host key. No firewall rule was reopened or changed by this task.

An isolated SSH checkout was created from the repository's baseline commit `6fdc1293f2fd9f354e60f3da070416e828792e0b`, on an owned test branch. It is retained for the explicit continuity probe. This is operator provisioning, not acceptance evidence for the W03 SSH provider.

No replacement API-created thread is used as a substitute. An attempted history read against an unselected session was rejected by automatic approval review and did not run.

The operator subsequently supplied the selected session and participated in the [actual enrolled-client proof](W01.4-client-continuity-2026-10-23.md). That later record closes the scoped continuity gate; the statuses below describe the upgrade handoff before that proof.
