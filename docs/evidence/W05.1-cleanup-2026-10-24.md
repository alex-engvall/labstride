# W05.1 — Cleanup selection, eligibility and retention evidence

Date: 2026-10-24. Requirements: LS-CLN-001, LS-CLN-002, LS-CLN-003. Implementation issue: #28. Environment: isolated Linux checkout, Node 24.22.0, local Git repositories, temporary SQLite stores, independently served local provider/target fixtures. No installed service, credential enrollment, production workspace, real PR, deployment or extension installation was changed.

## Accepted scope and implementation

The approved W05.1 slice provides optional configuration, two explicit completion policies, operator/completion triggers, pinned action assessment, independent observations, read-only Git inspection and durable pending handoff. W05.2 (#29) retains physical removal, filesystem quiescence/fencing, protected move and tombstones. The reference action cannot claim a removed directory: its output is `pending_executor`. An alternative pinned action retains work. The ordinary completed-run execution guard remains intact.

Requirements are `implemented` for this bounded profile, not `verified` for an installed/live cleanup environment. AC17/AC18/AC30 remain `not_run` at their full integration level, with the following scoped evidence. AC19/AC20 remain with #29; AC35/AC36 are unchanged.

## Observable local behavior

- **AC17 / LS-CLN-002:** A real owned checkout and independently confirmed local-provider merge enter assessment. Local keep, remote keep, unavailable control reads, busy/unsupported tracked sessions and human ownership prevent action invocation. A hold introduced during target inspection invalidates the decision. Local operator capabilities and expected workspace revisions protect keep changes; releasing local keep cannot override remote retention.
- **AC18 / LS-CLN-003:** Actual Git repositories exercise tracked edits, staged edits, untracked filenames containing newlines, ignored work, explicitly declared ignored caches, unpushed commits, detached HEAD, a branch outside HEAD, stashes, special index flags, shallow/incomplete history, stale tracking refs, removed remote branches, unavailable remotes and symlinked metadata. Tests fingerprint all source bytes, index, refs and configuration around inspection and assert no source changes. Declaring an untracked path regenerable never bypasses its blocker.
- **AC30 / LS-CLN-001:** A source-only workflow uses the operator trigger and public pending-handoff action. Another frozen configuration creates an actual recipe-owned SQLite database, selects the completion trigger and invokes a different pinned retaining action. The alternative action validates its own exact action identity. Behavior changes through configuration and normal extension loading. Both directories and runtime data remain present; no removal is inferred.
- **Completion-policy slice:** Existing W04 fixtures perform independent local merge/workflow/target effects. Cleanup rechecks direct verification and confirmed merge-to-successor ancestry, then reads current health/revision/resource identity again. Failed/unknown delivery, holds and conflicts block; expired historical health does not substitute for a fresh read. These fixtures intentionally retain other cleanup blockers and do not claim a completed directory-deletion scenario.
- **Native observation slice:** The bridge's new cleanup method reads metadata and turn summaries twice. Tests assert no resume, turn, interrupt or transcript recovery, and cover active and unavailable-history outcomes. This is a controlled adapter test, not a live interactive-client quiescence qualification.
- **Recovery:** Duplicate requests retain one identity. Lost action responses and actual child-coordinator `SIGKILL` immediately before or after assessment invocation recover the original persisted operation. A durable start counter proves start is not repeated. Epoch changes and changed holds reject old decisions. Pending assessment is never relabeled deleted.

## Remaining gates and recovery limits

- W05.2 must implement and qualify actual removal, mutation/session fencing, mounted/foreign-path protection and deletion acknowledgement recovery. Assessments expire; their presence does not authorize later deletion.
- The new connector capability, source-read credentials, configured remote keep binding, actual session backend, deployment observer and source history need installed/live qualification before enabling this profile. Root-operated SSH transport cases are not established by local/in-process fixture success.
- The initial Git profile verifies the enrolled source remote, refuses unsupported object graphs/index/submodule cases and bounds copied metadata and command output. It conservatively blocks when complete history or remote preservation cannot be established.
- No down migration exists. Restoring a compatible stopped-service backup preserves metadata but cannot reverse an external action. An uncertain action keeps its original identity; recovery observes it rather than replaying it.
