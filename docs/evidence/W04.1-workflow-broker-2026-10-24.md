# W04.1 local workflow broker evidence — 2026-10-24

This records the implementation and controlled local verification of issue #24, requirements LS-DEP-001/002/004 and the workflow boundary of LS-SEC-002. Accepted user scope is an opt-in coordinator integration with no installation changes, push, merge or deployment. The [protocol specification](../38-workflow-broker.md) describes the resulting contracts and recovery limits.

## Implemented behavior

- The pinned workflow action reads immutable enrollment from the run snapshot. Application SHA and workflow SHA remain separate through dispatch, claim, receipt and diagnostics.
- Dispatch intent is committed before one HTTP submission. Empty, run-ID and lost acknowledgements retain the original operation. Candidate discovery is followed by independent run-attempt validation; missing/ambiguous evidence never permits redispatch.
- GitHub OIDC verification and independent metadata checks precede a transactional runner claim. A separate one-time effect permission rechecks policy and controls. Coordinator and runner claims have separate roles; no expiry transfers execution authority.
- Receipts are authenticated and immutable. Duplicate receipts are accepted; conflicts retain the original and place a target hold. Independently observed workflow conclusion is required for workflow completion. No verified deployment is recorded.
- A loopback listener is opt-in, closes with the execution runtime, and requires separately managed HTTPS ingress. Existing broker-disabled configuration remains supported. Deployment-provider credentials remain outside coding inputs and coordinator operation payloads.
- Migration 14 is additive. Unknown outcomes retain original identities and locks; the workflow adapter continues bounded observation through repeated outages. There is no down migration or automatic uncertain-effect rerun.
