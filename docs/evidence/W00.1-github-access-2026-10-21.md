## Reproduce read probes

Use an already configured credential; never place token values in command arguments or this report. The following values select the observed public test targets and are replaceable installation inputs:

```bash
LABSTRIDE_PROBE_REPO=alex-engvall/labstride
LABSTRIDE_PROBE_OWNER=alex-engvall
LABSTRIDE_PROBE_PROJECT=8
LABSTRIDE_PROBE_SHA=b79bf3823e221481d3b93205881548218baea53b
gh --version
gh api user --jq '{login: .login}'
gh api -H X-GitHub-Api-Version:2022-11-28 "repos/$LABSTRIDE_PROBE_REPO/issues?state=all&per_page=1&page=1" --jq '.[].number'
gh api -H X-GitHub-Api-Version:2022-11-28 "repos/$LABSTRIDE_PROBE_REPO/issues?state=all&per_page=1&page=2" --jq '.[].number'
gh api -H X-GitHub-Api-Version:2022-11-28 "repos/$LABSTRIDE_PROBE_REPO/pulls?state=all&per_page=1" --jq '.[].number'
gh api -H X-GitHub-Api-Version:2022-11-28 "repos/$LABSTRIDE_PROBE_REPO/commits/$LABSTRIDE_PROBE_SHA/status" --jq '{state,total_count}'
gh api -H X-GitHub-Api-Version:2022-11-28 "repos/$LABSTRIDE_PROBE_REPO/commits/$LABSTRIDE_PROBE_SHA/check-runs" --jq '{total_count,checks:[.check_runs[]|{id,name,head_sha,conclusion}]}'
gh api -H X-GitHub-Api-Version:2022-11-28 "repos/$LABSTRIDE_PROBE_REPO/actions/runs?per_page=1" --jq '{total_count,runs:[.workflow_runs[]|{id,head_sha,conclusion}]}'
gh api -H X-GitHub-Api-Version:2022-11-28 "repos/$LABSTRIDE_PROBE_REPO/actions/workflows" --jq '{total_count,workflows:[.workflows[]|{id,path}]}'
gh api -H X-GitHub-Api-Version:2022-11-28 "repos/$LABSTRIDE_PROBE_REPO/hooks" --jq '[.[]|{id,active,events}]'
gh api graphql -f owner="$LABSTRIDE_PROBE_OWNER" -F number="$LABSTRIDE_PROBE_PROJECT" -f query='
query($owner:String!,$number:Int!){
  viewer{login} rateLimit{limit cost remaining resetAt}
  user(login:$owner){projectV2(number:$number){id public closed
    fields(first:100){totalCount pageInfo{hasNextPage endCursor} nodes{
      __typename ... on ProjectV2Field{id name dataType}
      ... on ProjectV2SingleSelectField{id name dataType options{id name}}
      ... on ProjectV2IterationField{id name dataType}
    }}
    items(first:1){totalCount nodes{id type} pageInfo{hasNextPage endCursor}}
  }}
}'
```

Repeat the items query with `items(first:1,after:$after)` and pass the returned cursor as a string variable using `-f after=...`. Page contents and counts may change. Do not dump full headers or credential configuration: record only API-version, scope and rate-limit response headers. The original contents probe used connector `fetch_file(repository_full_name, path="README.md", ref=source SHA, start_line=1, end_line=5)`; other connector reads and their limits are recorded in the matrix above.

## Reproduce the bounded write probe

Use a new unique fixture marker and the configured test Project. Resolve its project ID, a non-trigger single-select field ID and option ID from the live schema. Do not reuse the deleted item's ID above. Execute one mutation at a time with `gh api graphql -f query='...'` and variables passed using `-f project=...`, `-f item=...`, `-f field=...`, `-f option=...`, `-f title=...`, `-f body=...`, `-f marker=...` as required:

```graphql
mutation($project:ID!,$title:String!,$body:String!,$marker:String!){
  addProjectV2DraftIssue(input:{projectId:$project,title:$title,body:$body,clientMutationId:$marker}){
    clientMutationId projectItem{id type content{... on DraftIssue{id title}}}
  }
}
```

Persist the returned item ID before continuing. `clientMutationId` is a correlation marker, not a proven idempotency key. If the create response is lost, enumerate drafts by the unique title/body marker and reconcile; do not replay creation. Refuse to mutate or remove an item whose project, type and fixture identity cannot be established.

```graphql

  updateProjectV2ItemFieldValue(input:{projectId:$project,itemId:$item,fieldId:$field,value:{singleSelectOptionId:$option}}){projectV2Item{id}}
}
```

Independently query the item and verify the selected option. The executed query used `fieldValueByName(name:"Priority")`; a different installation must use its configured field and resolved ID, not assume this name. Then clear and independently read back `null`:


Verify absence by enumerating all current project items with cursors. A response lost around a write or deletion is an uncertain outcome; read current state before deciding any further action. None of these ambiguous-response cases were injected during this discovery.
