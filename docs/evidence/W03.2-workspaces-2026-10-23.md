## Implemented behavior

The public pinned workspace action, SSH connector 1.1.0, v2 helper contracts and additive target registry create an independent checkout of the exact source SHA. A protected journal and marker retain initial ownership and filesystem identity. The ordinary worker records preparation at its effect boundary and accepts readiness/resources transactionally. Reconciliation observes the original published checkout without running Git in coding-controlled content or overwriting later edits.

The [normative contract](../34-exact-revision-workspaces.md) describes source allowlisting/authentication, exact generated identities, permissions, uncertainty and rollback limits. Existing reservation responses remain v1. Original releases, pins, reservations and resources are retained.

Later additions and final pilot totals are recorded separately below; this initial count is not a final release count.

They verify separate clones/branches, unchanged exact initial SHA, conflicting directories/symlinks, digest/owner conflicts, retained partial stages, concurrent duplicate claims, missing commits and preservation of later human edits. The actual helper verifies API metadata and uses real Git HTTPS fetches. Receipt, stderr and checkout configuration checks exclude the synthetic secret. This qualifies the transport/authentication implementation; it does not qualify a real private GitHub repository or an operator credential's least privilege/expiry.
