# W01.1 — Resource and evidence retention

Date: 2026-10-21. Requirements: LS-CORE-001 and LS-CORE-006. Issue: [#14](https://github.com/alex-engvall/labstride/issues/14). First slice: [PR #44](https://github.com/alex-engvall/labstride/pull/44) and [lifecycle evidence](W01.1-lifecycles-2026-10-21.md).

## Executed behavior

The [retention tests](../../tests/lifecycle-retention.test.mjs) use the actual coordinator/bootstrap/store on Linux x86_64, Node `24.22.0`, SQLite `3.53.4`. The local filesystem fixture is owned entirely by the tests; provider/session/workflow identities and evidence references are synthetic. No installed target action or workflow receipt is claimed.

| Test | Observed result |
| --- | --- |
| Physical workspace removal | Created a temporary workspace and separate sentinel directory, persisted run/resource/PR/merge/deploy metadata, wrote a test tombstone outside the workspace, removed only the owned workspace and recorded cleanup. A reopened coordinator retained all evidence, original resource identities and audit; the sentinel content remained unchanged. |
| Immutable evidence and corrections | Both the typed store and SQLite rejected evidence/resource mutation. A correction appended a linked record while the original verified observation remained readable. Parent workspace deletion was rejected. |
| Invalid resource/evidence identities | Mismatched ownership/source, a verified cleanup without tombstone and a correction without an original were rejected without partial writes or audit. |
| State/workspace overlap | Nested/equal/ancestor paths and relative paths were rejected, including before state-directory creation and during a batch after earlier inserts; rollback left no records. |
| Canonical aliases | Repointing a registered workspace symlink to the state directory blocked subsequent startup. Configured alias overlap and unresolved dangling links were rejected. |
| Linked database/journals | Symlinked database/WAL/SHM/journal files and a hard-linked database were rejected before opening; the unrelated target bytes were preserved. |
| Upgrade/failure | A genuine v1 database with original records/audit upgraded through migration v2. IDs, sessions, revisions and audit survived. A failing next migration rolled back DDL/version and left the full history unchanged. |

Validation commands: `npm run check:types`; `npm test`; `python -m unittest discover -s tests -p 'test_*.py'`; `python scripts/validate_docs.py`. Python uses the pinned documentation dependencies and required format checkers. Node tests require child processes/loopback sockets. The final suite contains 105 Node tests (89 previous, nine lifecycle and seven retention cases), plus four Python tests and documentation/type checks.
