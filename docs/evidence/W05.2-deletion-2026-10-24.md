## Accepted scope and adopted design

The operator approved the conservative Linux deletion profile and isolated verification in this session. The implementation adds a separately pinned execution capability, protected target ownership and fencing, prepare/commit authorization, same-filesystem movement, descriptor-based removal and immutable tombstones. It preserves the v1 assessment path and original operation identity after uncertainty. Cleanup is still a configured replaceable action; runtime resources remain separately owned.

The public cleanup action is 1.1.0 (`cleanup.assess.v1`, `cleanup.execute.v1`); the SSH connector is 1.5.0 (`cleanup.delete.v1` added). Target schema v3 retains earlier reservation/workspace messages; coordinator migration 19 adds a separate retained deletion journal. The trusted helper policy must explicitly qualify `linux-exclusive-writers.v1`. No installed configuration was changed to enable it.

LS-CLN-004/005 are `implemented`, not `verified`. Successful-removal fixtures use actual registry ownership, access changes, Git inspection, rename, recursive removal, durable tombstones and coordinator reconciliation, with an injected trusted quiescence seam and local source transport. This is not evidence that an installed root helper established real process quiescence. The unprivileged production guard refuses this checkout; root-operated process/mount/ownership and real SSH cases have explicit skips. Full AC17/AC18/AC19/AC20/AC30 remain `not_run`; existing AC35/AC36 evidence/status is unchanged.

## Observable behavior and acceptance slices

- **LS-CLN-004 / AC19:** Actual symlink, foreign-directory, source-directory, root and parent substitutions are refused. Additional substitutions occur after fencing and immediately at the move boundary. Unrelated content and saved original directories survive. Destination collisions, hardlinks, unsupported policy, unexpected wrapper entries, dirty/untracked/undeclared ignored work and simulated writer/visibility failures retain the directory. Internal ignored-cache symlinks are unlinked without traversing external targets. Real bind-mounted directory/file/wrapper and foreign UID cases require the skipped privileged environment.
- **LS-CLN-005 / AC20:** Actual helper `SIGKILL` covers durable intent, access fencing, prepared receipt, moving intent, completed rename, partial recursive removal, completed removal and persisted tombstone. Recovery either retains pre-move uncertainty or finishes only the protected captured resource. A new directory at the former locator survives all post-move reconciliations. Repeated completion returns the original tombstone; SQL triggers refuse tombstone mutation or deletion.
- **Coordinator AC20 slice:** Actual coordinator `SIGKILL` before target preparation preserves one unknown operation and never repeats start. Killing it after target deletion but before acknowledgement leaves the coordinator in `deleting`; restart independently reads the original target tombstone, appends cleanup evidence and marks `deleted`. The original merge record and resource/run history survive, and a replacement directory remains intact.
- **Eligibility and dispatch:** Local/remote keep, pause and recovery changes after preparation prevent commit and restore confirmed retention. Prepared decisions and commit authorization bind context, epoch, generation, immutable operation and a bounded expiry. Lost prepare/commit acknowledgements reconcile without a second start/commit. An action result without independent target evidence cannot establish deletion.
- **Compatibility and concurrency:** An assessment-only frozen 1.0.0 artifact remains pending; alternate retaining actions remain supported. Migration coverage retains prior assessments and all earlier operation/dispatch/receipt identities without inventing deletion. A protected deletion owner prevents a competing operation and runtime attachment; active target runtime use prevents fencing. SQLite serialization releases on actual process death while durable ownership remains.

The process-check seam is injected through a trusted test embedding API, never policy, issue data or wire input. Production entrypoints supply no override. Negative process-visibility behavior, actual removal/recovery and privilege-dependent acceptance are separate evidence categories.

## Remaining gates and recovery limits

- Qualify the actual root helper, complete host PID/user/mount visibility, source credentials, coding identity, process churn, nested directory/file mounts, ACL/namespace assumptions and SSH transport before enabling installed deletion. Container-local proc visibility is insufficient even when it appears readable. Root/helper code is trusted and must respect workspace fencing.
- This profile rejects every unprivileged process, including unrelated processes. It does not kill processes or introduce cgroup/process isolation. Missing, restricted or changing visibility blocks cleanup; idle provider metadata is never the filesystem fence. Wider shared-host availability needs another qualified profile.
- A prepare not observed by the target stays uncertain and is not replayed. A moving intent with no captured destination retains the original fence as `move_unknown`; recovery never retries rename from the former locator. These cases need operator investigation of the retained original identities. A definite pre-move release can restore access; an uncertain or moved resource cannot be unlocked by a new request.
- A durable removing phase can finish only inside its original protected deletion area. An unexplained missing path cannot become a verified deletion. No down migration or automatic retry of an uncertain side effect exists. Backup restoration cannot restore removed files or undo an external effect.
- Installed session/deployment/completion integration, runtime disposal, power-loss durability and broader platforms remain unverified. Local `SIGKILL` is actual process-crash evidence, not a machine power-loss test.
