## Initial integration profile and hook mapping boundary

**Adopted technical profile:** Labstride hook ingestion is disabled and no raw Codex hook capability is advertised for the first integration. This is a safe initial profile within the existing optional-hook design, not a new product decision, a global Codex feature toggle or a claim that settings were changed. Manual client use and public agent-independent work remain in scope. Automated session effects requiring unavailable atomic guards must remain paused/unsupported; disabling hooks does not repair those guards.

The inspected `HookEventName` inventory contains `sessionStart`, `sessionEnd`, `stop`, `interrupt`, `userPromptSubmit`, `preToolUse`, `permissionRequest`, `postToolUse`, `preCompact`, `postCompact`, `subagentStart` and `subagentStop`. These are protocol spellings; configuration uses names such as `SessionStart` and `Stop`. No listed event was delivered in this discovery.

The following is the adopted mapping boundary for a future adapter, **not an enabled or verified translator**. Missing required provider evidence means no normalized event is emitted. In this profile every raw event remains disabled.

| Codex event | Possible normalized observation after authoritative correlation | Excluded inference |
| --- | --- | --- |
| `SessionStart` | `session.ready` only after the enrolled backend confirms readiness | A start callback alone is not readiness or permission to resume. |
| `Stop` | `turn.stopped` only after the backend confirms the enrolled turn actually stopped at the recorded source revision | Callback identity alone is insufficient: a stop hook can request continuation. Not task completion, plan approval or permission for another turn. |
| `Interrupt` | `turn.interrupted` after confirming interruption of the enrolled turn | Not proof that external effects were cancelled. |
| `SessionEnd` | `session.closed` only if authoritative session state confirms the same meaning | Not a cleanup grant; backend unloading must not be equated with permanent session closure. |
| `UserPromptSubmit` | No direct v1 hook mapping | Not an atomic human revision or proof that a turn started. Never retain prompt content. |
| `PermissionRequest` | No direct v1 hook mapping | Not `question.pending`, approved policy or a human plan decision. |
| `PreToolUse`, `PostToolUse`, `PreCompact`, `PostCompact`, `SubagentStart`, `SubagentStop` | No v1 core mapping | No tool arguments, results, transcripts or inferred root-session lifecycle. |
| No supported raw hook established | `turn.started` and `question.pending` require separately verified backend observations | Do not synthesize them from prompt, permission or tool activity. |

This table is a Labstride design constraint. The upstream [hook reference](https://learn.chatgpt.com/docs/hooks) describes lifecycle signals, hash-based trust review and project trust; its `Stop` behavior can create a continuation, so that callback is not a terminal-state receipt. Non-managed definitions need review of their exact current hash; modified definitions require renewed trust. Background delivery can be interrupted, so it cannot replace durable reconciliation. No trust bypass is part of this profile.

Before any optional hook can be enabled, the session-provider implementer must supply a versioned adapter and evidence for all of these gates:

1. Pin the provider version, supported event semantics and exact reviewed definition/handler; verify installed source, enablement, project trust where relevant and definition trust. Treat unknown/modified/untrusted definitions as unavailable. This PR installs or trusts nothing.
2. Resolve provider/run/request-generation/workspace/session/turn from trusted enrollment and supported backend facts. A caller-supplied session ID or working directory is insufficient. Missing timestamps, source revisions or identity facts must not be invented to satisfy the v1 schema.
3. Persist the normalized record and stable event/delivery identity before retrying transport. Raw callbacks are not assumed to supply a stable event ID: without one, reconcile authoritative revisions instead of claiming raw-callback deduplication. Reuse the same normalized identity on retry; conflicting content under that identity is rejected. Strip private/raw fields and validate before persistence/projection effects.
4. Implement the coordinator observation/outbox transaction before acknowledging durable acceptance; test a lost reply, duplicates, late/missing events and projection failure. A successful hook process exit is not this acknowledgement. Preserve unknown effects instead of replaying them.
5. Prove backend reconciliation with hooks disabled and demonstrate the actual enrolled client's continuity and human-priority limits. Only then advertise the tested capability through explicit installation configuration. A new version or definition requires requalification.

These are future enablement/integration gates with owners below. The initial disabled profile resolves the discovery choice without requiring a live hook installation, additional credentials or repetition of the operator's manual smoke tests.
