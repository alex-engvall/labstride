## Reproduction and limits

Use an operator-approved test repository and a dedicated App token with explicit repository IDs/permission subset. Read the repository's applicable instructions and all triggering workflows first, including auto-deployment source branches and contribution requirements. Refuse to continue if the base changed after that review or the proposed fixture path/ref already exists. Do not use main as the test branch.

The actual write sequence was:

1. `POST /repos/{owner}/{repo}/git/refs` with the unique `refs/heads/feature/codex/...` and reviewed base SHA.
2. `PUT /repos/{owner}/{repo}/contents/{synthetic_path}` with a bounded commit message, base64 synthetic content and explicit test branch. Read the returned file at the returned commit and verify exact bytes, blob hash, parent and branch head.
3. Repeat PUT with changed fixture content and the first response's blob SHA. Repeat independent reads. Never replay a lost write acknowledgement.
4. `POST /repos/{owner}/{repo}/pulls` with the fixture branch, reviewed base branch, explicit synthetic description and `draft:true`. Read the PR and complete changed-file list. Attach the created PR to the operator's task.
5. Read `GET /actions/runs?head_sha={exact_head}` and each matched run and job. Bind workflow ID/path, event, actor, attempt, PR number, head and base. Independently read `/commits/{exact_head}/check-runs`; do not count an older successful run or missing checks as success.
6. Wait for terminal results without rerunning or granting more permissions. Record the outcomes before cleanup.
7. PATCH the owned PR's body/state, independently verify the final body and closed/unmerged state, then compare the owned branch against its recorded base/head and exact changed paths. Delete only if the known fixture history has not advanced and no open PR uses it. Verify ref absence, unchanged main and fixture absence. Preserve unexpected or uncertain state instead of replaying cleanup.

This proves the observed App-token PR-trigger path. It does not prove workflow dispatch, merge execution, deployment, protection enforcement, all event/credential combinations, private repository support or recovery after a deliberately lost acknowledgement. File deletion through the Contents API was not tested.
