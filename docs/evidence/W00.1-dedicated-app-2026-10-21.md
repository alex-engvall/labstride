## Reproduction contract

Use the installation-local App/client/installation identities and key reference; never substitute the owner's normal CLI credential. Sign an RS256 App JWT, call `GET /app` and `GET /app/installations`, and compare owner, grant map and selected-repository policy before minting any installation token. App authentication and token generation are documented in the [setup guide](../25-github-app-setup.md).

The token request is `POST /app/installations/INSTALLATION_ID/access_tokens`, with `permissions` set to the probe's exact subset. The initial installation inventory probe intentionally omitted `repository_ids` and requested only `{"metadata":"read"}` so it could enumerate the complete installation set. All later probes supplied `"repository_ids":[1423904962]`. Do not emit the response's `token` field. Revoke the token when the bounded probe finishes.

For read reproduction, authenticate a CLI/HTTP client with that App token in its environment or in-memory header (never a token argument). Example CLI commands assume `GH_TOKEN` has been injected for just this process, not that the normal `gh` login has changed:

```bash
gh api -H X-GitHub-Api-Version:2022-11-28 'repos/alex-engvall/fortnox-mcp/issues?state=all&per_page=1&page=1' --jq '.[].number'
gh api -H X-GitHub-Api-Version:2022-11-28 'repos/alex-engvall/fortnox-mcp/issues?state=all&per_page=1&page=2' --jq '.[].number'
gh api -H X-GitHub-Api-Version:2022-11-28 repos/alex-engvall/fortnox-mcp/actions/workflows --jq '{total_count}'
gh api graphql -f query='query{user(login:"alex-engvall"){projectV2(number:8){id public fields(first:1){totalCount}}} rateLimit{limit cost remaining}}'
```

The Project write probe used `addProjectV2DraftIssue` with variables containing the live-resolved Project ID and a unique fixture marker as title/clientMutationId. It used the App's complete grant map in the table above, so rejection was not merely caused by using a read-only token. No create retry was attempted; no item ID was returned. See the [initial probe recipe](W00.1-github-access-2026-10-21.md) for mutation shape and uncertain-outcome handling. Do not reuse an old fixture marker.

The issue write probe used `POST /repos/{owner}/{repo}/issues` with a bounded synthetic title/body and no labels/assignees, independently fetched the returned issue, then used `PATCH /repos/{owner}/{repo}/issues/{number}` with `{"state":"closed","state_reason":"not_planned"}` and independently fetched the final state. Replay creates a different external issue, so reconcile a missing response by marker and preserve the original identity instead of retrying. The completed fixture is #80; do not alter it to reproduce the probe.
